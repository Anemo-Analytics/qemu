# status 2026-05-03

short version: gate 7 closed, bsp now reads real bytes from `/fs/`

35 tasks running, was 21.

## what got us through

stack-walked tRootTask.. sat in PEND on a sem inside usrToolsInit's
printf banner.. a never-fired PSC1 TX-empty IRQ.

dropped a 2-instruction patch at 0x2acee8 (`li r3,0; blr` -- nop
the printf), then moved the patch installer off the 60Hz tick
(too late, ~1s delay) onto the diag sampler so it lands within ~1µs
of code being mapped.

bsp now walks past the banner.. usrAppInit fires.. all the
firedrake daemons spawn (ftpd, portmap, nfs, t1ServerTask,
t1KeepAliveTask, etc).

## the honest gap

nc handshakes to localhost:{2121,3111,2049,17185,9482,8080} all
succeed.. but thats slirp accepting locally, not proof of guest
delivery.

real byte reads (ftp banner, raw firedrake on 9482, http GET on
8080) all time out -- zero bytes back.

qemu log shows BestComm RX walker fires 56 times.. every single
one drops with "BD not READY". slirp IS forwarding to the FEC,
but the receive descriptor ring isnt being re-armed.

tFecEndRx is PEND'd on a sem at PC=0x2fe918.. the task that
should re-arm BDs after RX events.. never wakes.

so: FEC RX-done IRQ never fires. same family of problem as the
PSC1 TX IRQ we worked around with the printf nop. without IRQ
delivery there is no two-way comms with the guest, no matter
how many daemons exist.
